## What a linear layer does

A linear layer maps an input vector to an output vector via a learned weight matrix and bias:

$$y = xW + b$$

where $x$ is $[N, \text{in}]$, $W$ is $[\text{in}, \text{out}]$, $b$ is $[1, \text{out}]$, and $y$ is $[N, \text{out}]$. The weight matrix $W$ contains every connection between input and output neurons.

<div class="callout">
**Engineer's Note: Why Matrices?**

We use matrices not just because the math is elegant, but because of **Hardware Symbiosis**. Modern CPUs and GPUs are fundamentally designed to execute massive blocks of floating-point math in parallel (via SIMD instructions). If you used a simple network of objects (where every neuron is a `class Neuron { std::vector<float> weights; }`), iterating through them would cause constant cache misses and branch mispredictions. Packing everything into a dense flat matrix ($W$) allows the CPU to calculate thousands of connections in a single hardware instruction.

**The Golden Sanity Check:**
90% of C++ AI bugs are simply "Dimension Mismatch" crashes. Before you compile, write down your shapes. If $X$ is $(B, M)$ and $W$ is $(M, N)$, the inner dimensions ($M$) must match, and the output MUST be $(B, N)$. If it's not, your code will segfault.
</div>

## Matrix multiplication

The output $y_{ij} = \sum_k x_{ik} W_{kj}$ — each output element is a dot product between a row of $x$ and a column of $W$. This is `matmul` in the framework.

Let's look at this through the lens of the "Seabird Survival" dataset. If we have 32 birds in a batch, and each bird has 10 features, our input $x$ is a `[32, 10]` matrix in memory. If our first hidden layer has 64 neurons, $W$ is `[10, 64]`. 

One single matrix multiplication `matmul(x, W)` processes the *entire flock of 32 birds simultaneously*, outputting a `[32, 64]` tensor.

The gradient with respect to $W$ is:

$$\frac{\partial L}{\partial W} = x^T \cdot \frac{\partial L}{\partial y}$$

and with respect to $x$:

$$\frac{\partial L}{\partial x} = \frac{\partial L}{\partial y} \cdot W^T$$

In flat-index terms, `gradX[i,k]` accumulates `grad[i,j] * W[k,j]` over all j, and `gradW[k,j]` accumulates `X[i,k] * grad[i,j]` over all batch rows i — exactly what the loops below compute.

```cpp
// From src/ops/matmul.cpp — backward pass
// X is [M, K], W is [K, N], grad is [M, N]
void MatmulOperation::backward(const std::vector<float>& grad) {
    int M = t1->shape[0], K = t1->shape[1], N = t2->shape[1];
    std::vector<float> gradX(M * K, 0.0f);  // grad w.r.t. X
    std::vector<float> gradW(K * N, 0.0f);  // grad w.r.t. W

    // gradX = grad @ W^T: row i of gradX is dot of grad row i with each col of W^T
    for (int i = 0; i < M; ++i)
        for (int k = 0; k < K; ++k)
            for (int j = 0; j < N; ++j)
                gradX[i*K + k] += grad[i*N + j] * t2->data[k*N + j];

    // gradW = X^T @ grad: entry (k,j) of gradW sums over all batch rows
    for (int k = 0; k < K; ++k)
        for (int j = 0; j < N; ++j)
            for (int i = 0; i < M; ++i)
                gradW[k*N + j] += t1->data[i*K + k] * grad[i*N + j];

    t1->accumulate_grad(gradX);
    t2->accumulate_grad(gradW);
}
```

<div class="callout">
**C++ Performance: The Nested Loop Reality**

Our educational C++ code above uses a naive triple-nested `for` loop ($O(N^3)$). While mathematically correct, this is extremely slow for large matrices. 

In industrial frameworks (or when you are ready to optimize your C++ engine), you would never write this loop manually. You would use **SIMD intrinsics** (AVX2/AVX-512) to process 16 floats at a time, or **OpenMP** to parallelize the outer loop across all CPU cores. Better yet, you would link against a highly optimized BLAS library like OpenBLAS or Intel MKL. The jump from a basic $O(N^3)$ loop to a cache-blocked SIMD implementation is where C++ engineering gets truly fun!
</div>

## Xavier initialization

Weights can't all start at zero (all neurons would learn the same thing) and can't be too large (activations explode through layers). Xavier initialization sets the standard deviation based on the layer size:

$$W \sim \mathcal{U}\left(-\sqrt{\frac{6}{\text{in} + \text{out}}}, \sqrt{\frac{6}{\text{in} + \text{out}}}\right)$$

This keeps the variance of activations roughly constant across layers at initialization.

```cpp
// From nn/Linear.h — Xavier initialization
float limit = std::sqrt(6.0f / (in_features + out_features));
std::uniform_real_distribution<float> dist(-limit, limit);
for (auto& w : weight.data) w = dist(gen);
```

## Module lifetime and raw pointer storage

Operations in this framework hold **raw pointers** to their input tensors. The matmul operation created by `matmul(input, weights)` stores `input*` and `weights*` internally — it needs them during the backward pass to compute gradients.

This creates a C++ lifetime requirement: the tensors pointed to must outlive the operation. If a local `Tensor input` goes out of scope before `backward()` is called, the operation is holding a dangling pointer.

`nn::Linear` solves this by storing copies as member variables:

```cpp
// From nn/Linear.h — storing tensors to keep them alive
class Linear : public Module {
    Tensor input_copy; // kept alive — matmul holds raw pointer to this
    Tensor mm_result;  // kept alive during backward pass
public:
    Tensor forward(const Tensor& input) override {
        input_copy = input;                       // copy into member
        mm_result  = matmul(input_copy, weights); // operation points into member
        return mm_result + bias;
    }
};
```

Without `input_copy`, the matmul operation's input pointer would dangle as soon as `forward()` returned. Python frameworks hide this entirely — tensor lifetimes are managed by reference counting. In C++, it's the module's responsibility. Every module in this framework (Linear, Conv2d, BatchNorm, Dropout) stores intermediate tensors as members for exactly this reason.

## XOR: the simplest non-trivial network

XOR is not linearly separable — no single line separates (0,0),(1,1) from (0,1),(1,0). You need at least one hidden layer to solve it. This makes it the canonical test for a working backprop implementation.

```cpp
// From main.cpp — XOR training with 2-layer network
nn::Sequential model({
    std::make_shared<nn::Linear>(2, 4),
    std::make_shared<nn::Tanh>(),
    std::make_shared<nn::Linear>(4, 1),
    std::make_shared<nn::Sigmoid>()
});
// After ~2000 epochs with Adam lr=0.01: loss < 0.01, XOR solved
```

<div class="callout">
If your backprop is wrong, XOR will not converge — or will converge to 0.5 (the network learns a constant). It's the fastest smoke test for a new autodiff implementation.
</div>
