## Why nonlinearity matters

A stack of linear layers without activations is mathematically just one big linear layer:

$$W_2(W_1 x + b_1) + b_2 = (W_2 W_1)x + (W_2 b_1 + b_2)$$

*The Seabird Perspective:* If we used a linear activation for every layer in the Seabird model, would stacking 10 layers make it perform better than a single layer? **No.** Two linear matrices multiplied together just form a new linear matrix ($W_{new} x$). You could stack a thousand layers, and it would still only draw a single straight line.

Non-linearity is the *only* reason "Deep" Learning exists. Activations warp the mathematical space, allowing the network to fold and curve its decision boundaries around complex data. Without this lesson, the rest of the course is just basic linear algebra.

## ReLU

$$\text{ReLU}(x) = \max(0, x)$$

The simplest useful activation. Gradient is 1 for positive inputs, 0 for negative. It seems too simple to be powerful, but its "sparsity" is its strength: by completely turning off negative neurons, the network becomes highly efficient.

<div class="callout">
**The "Dying ReLU" Warning**

If a neuron's weights are initialized so poorly that it *always* outputs a negative value for your entire dataset, it will never "fire" again because its gradient becomes exactly 0. It becomes a "Dead Neuron," permanently useless. This is mitigated by good initialization and careful learning rates.
</div>

**C++ Implementation Pattern**: Notice below that activations are purely *Element-wise* operations. Unlike MatMul, they do not care about neighboring data. This makes them perfectly suited for massive SIMD (AVX) optimization, and makes their backward pass incredibly fast (just a simple scalar multiplication).

```cpp
// From src/ops/activations.cpp — ReLUOperation backward
void backward(const std::vector<float>& grad) override {
    std::vector<float> dx(grad.size());
    for (size_t i = 0; i < grad.size(); ++i)
        dx[i] = (t1->data[i] > 0.0f) ? grad[i] : 0.0f;
    t1->accumulate_grad(dx);
}
```

## Sigmoid

$$\sigma(x) = \frac{1}{1 + e^{-x}}$$

Squashes any input to $(0, 1)$. Used in binary classification output layers (`BCELoss`). Gradient: $\sigma'(x) = \sigma(x)(1 - \sigma(x))$.

*(Numerical Stability Tip: In C++, calculating $e^{-x}$ for a very large negative $x$ leads to a massive float overflow. A pro-level implementation uses the "exp-normalize trick" or clips values before exponentiation to avoid `inf` or `NaN` crashes).*

Problem: **The Vanishing Gradient**. (Try viewing the Derivative on the interactive graph!). The gradient of a Sigmoid function reaches its absolute maximum at $x=0$, where $\sigma'(0) = 0.25$. 

Because of the chain rule, gradients are multiplied backwards through the network. If you have a deep network with 10 hidden layers, the gradient signal is multiplied by at most $0.25$ ten times: $0.25^{10} \approx 0.0000009$. The gradient effectively vanishes before reaching the early layers, meaning they never learn.

This mathematical bottleneck is exactly why deep neural networks failed to scale in the early 2000s (when Sigmoid was the default activation in tools like NeuralWorks). The shift to ReLU (which has a gradient of $1.0$) was the breakthrough that made modern Deep Learning possible. Today, Sigmoid is rarely used in hidden layers.

## Tanh

$$\tanh(x) = \frac{e^x - e^{-x}}{e^x + e^{-x}}$$

Tanh is essentially a shifted and scaled Sigmoid. 

**The Advantage:** Being "zero-centered" means the average output of the neuron is closer to zero. This keeps the data normalized, which helps the next layer learn significantly faster.

*The History:* Tanh was the absolute "Gold Standard" before ReLU took over. If you were building the Seabird project today without modern frameworks, Tanh would likely be your first choice for the hidden layers. It still suffers from vanishing gradients at saturation, but less severely than Sigmoid.

Tanh is used in the XOR demo (hidden layer) because it works well with small networks on small data.

## Softmax

For multi-class classification (e.g., 10 MNIST classes), the output layer uses softmax. 

*(Note: Softmax is a "Special Case" activation. Unlike ReLU or Sigmoid, which only look at a single float at a time, Softmax looks at the entire vector simultaneously to create a probability distribution that sums to 1.0).*

$$\text{softmax}(x)_i = \frac{e^{x_i - \max(x)}}{\sum_j e^{x_j - \max(x)}}$$

The $\max(x)$ subtraction is numerical stabilization — it prevents overflow when $x_i$ is large. Softmax is fused with cross-entropy loss in this framework (they share a backward pass that cancels neatly — see [Lesson 8: MNIST Capstone](/lessons/08-mnist-capstone) for the full derivation).

<div class="callout">
In practice: use ReLU in hidden layers. Use Sigmoid only for binary output, Softmax (via CrossEntropyLoss) for multi-class output. Tanh is a reasonable choice for small networks where ReLU dying is a concern.
</div>

## Numerical Stability in Practice

The mathematical definitions of activation functions are clean, but real floating-point arithmetic creates subtle problems. Understanding these is crucial for building models that don't silently produce NaN or infinite values.

### Sigmoid and Tanh Saturation

Sigmoid: $\sigma(x) = \frac{1}{1 + e^{-x}}$

For large positive $x$ (e.g., $x = 100$):
- $e^{-x} \approx 0$, so $\sigma(x) \approx 1$
- **Derivative:** $\sigma'(x) = \sigma(x)(1 - \sigma(x)) \approx 1 \cdot 0 = 0$
- **Result:** Gradient vanishes to machine epsilon

This is **saturation**: the function is flat, so gradients can't flow backward.

**In practice:** Sigmoid/Tanh saturate after |x| > 6. In deep networks without careful initialization, early layers produce |x| > 10, saturating the entire network.

**Fix:** Use ReLU (no saturation except at 0) or ensure careful initialization (which we covered in lesson 3.5).

### Softmax Overflow

Softmax: $\text{softmax}(x_i) = \frac{e^{x_i}}{\sum_j e^{x_j}}$

If any $x_i > 700$:
- $e^{700}$ overflows (exceeds float32 max ~3.4e38)
- Result is `inf`, then `inf / inf = NaN`
- **The entire batch is ruined.**

**Log-sum-exp trick:** Subtract the maximum before exponentiating:

$$\text{softmax}(x_i) = \frac{e^{x_i - \max(x)}}{\sum_j e^{x_j - \max(x)}}$$

This is mathematically equivalent (the $e^{-\max(x)}$ cancels in numerator and denominator) but numerically safe:
- Max value input to exp: 0
- All exponents are $\leq 0$
- All results are in (0, 1], never overflow

**In tensorflowccp:**

```cpp
// Stable softmax implementation
Tensor softmax(const Tensor& x) {
    Tensor max_x = max(x, axis=1);  // Shape: (batch_size, 1)
    Tensor shifted = x - max_x;      // Broadcast subtraction
    Tensor exp_x = exp(shifted);     // Safe: all values ≤ 0
    Tensor sum_exp = sum(exp_x, axis=1);  // Sum per row
    return exp_x / sum_exp;
}
```

### Gradient Clipping for RNNs

During backprop through time (BPTT), gradients can explode if weights are large or sequences are long. A common fix: **gradient clipping**.

Before optimizer step, clip the gradient norm:

```cpp
// After loss.backward(), before optimizer.step()
float grad_norm = 0.0f;
for (auto param : model.parameters()) {
    grad_norm += std::pow(param->grad.norm(), 2);
}
grad_norm = std::sqrt(grad_norm);

if (grad_norm > MAX_GRAD_NORM) {
    for (auto param : model.parameters()) {
        param->grad *= MAX_GRAD_NORM / grad_norm;  // Scale down
    }
}
```

This prevents extreme updates that would corrupt learned representations.

### Key Stability Insights

1. **Sigmoid/Tanh** saturate → use ReLU or manage initialization
2. **Softmax** overflows → use log-sum-exp trick
3. **Gradients** can explode → use gradient clipping in RNNs/Transformers
4. **Batch norm** helps → normalizes activations to a reasonable range, preventing saturation
5. **Test with large inputs** — if you only test with default PyTorch shapes, you won't catch overflow

These details separate code that "works on toy data" from code that works in production.
