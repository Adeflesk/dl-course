## Why not just use linear layers on images?

A 28×28 grayscale image is 784 numbers. A linear layer from 784 → 128 has 784×128 = 100,352 parameters — for just one layer. 

Worse: a linear layer treats every pixel independently, ignoring spatial structure. Imagine if the Seabird project used photos instead of stats. With a Linear Layer, if a bird was in the top-left of the photo, the network would learn weights to detect a "Bird" there. If the same bird appeared in the bottom-right, the network would have to learn "Bird-ness" all over again from scratch!

Convolutional layers fix both problems: fewer parameters via **weight sharing**, and **Translation Invariance** via sliding kernels. Once a CNN learns a "Wing" kernel, it can find that wing anywhere in the image.

## Convolution

A **kernel** (also called a filter) is a small weight matrix — typically 3×3 or 5×5. It slides over the input image, computing a dot product at each position. The result is a **feature map**: the activation of that kernel at every spatial location.

For a 5×5 kernel on a 28×28 input with no padding:
$$\text{output size} = 28 - 5 + 1 = 24$$

The output is 24×24. With 8 kernels, the output is 8×24×24 — 8 feature maps, one per kernel.

*(Padding Note: Notice the image shrank from $28$ to $24$. This is called "Valid" convolution. If we wanted to keep the image at $28 \times 28$, we would add a border of zeros around the input, known as "Same" padding. For our MNIST project, we stick to Valid convolution for educational simplicity).*

```cpp
// From src/ops/conv2d.cpp — forward pass (pseudocode; actual uses flat-index arithmetic)
for (int n = 0; n < N; ++n)
  for (int oc = 0; oc < OC; ++oc)
    for (int oh = 0; oh < OH; ++oh)
      for (int ow = 0; ow < OW; ++ow) {
        float sum = bias[oc];
        for (int ic = 0; ic < IC; ++ic)
          for (int kh = 0; kh < KH; ++kh)
            for (int kw = 0; kw < KW; ++kw)
              sum += input[n,ic,oh+kh,ow+kw] * kernel[oc,ic,kh,kw];
        output[n,oc,oh,ow] = sum;
      }
```

The 7-nested loop above is the absolute mathematical "Truth" of Convolution. However, in industrial frameworks, we don't actually execute these loops directly. 

Instead, we use an algorithm called `Im2Col` (Image to Column). It transforms the image patches and the kernels into two massive 2D matrices. We then feed them into the highly optimized SIMD/BLAS Matrix Multiplication engine we discussed in [Lesson 04](/lessons/04-linear-layers). Ultimately, almost everything in Deep Learning compiles down to a fast MatMul!

**Weight sharing**: all 576 positions in a 24×24 feature map use the same 25 kernel weights. This is the key efficiency — 8×1×5×5 + 8 bias = 208 parameters instead of millions.

## Pooling

After convolution, we typically subsample with a pooling layer. **MaxPool2d(2)** takes the maximum value in each 2×2 window, halving both spatial dimensions:

$$28\times28 \xrightarrow{\text{Conv2d(1,8,5)}} 8\times24\times24 \xrightarrow{\text{MaxPool(2)}} 8\times12\times12$$

Pooling reduces computation and adds mild translation invariance — a feature shifted by 1 pixel still activates the same max.

### MaxPool backward

*(Senior Engineer Insight: Notice below that the network must "remember" its state. We must store the `argmax` index during the forward pass so we know exactly where to route the gradient during the backward pass!)*

During the forward pass, each pooling window records which input position had the maximum value — this is the **argmax index**. During backward, the gradient for that output position routes entirely to the argmax input position. Every other position in the window gets zero gradient.

```cpp
// From src/ops/pool.cpp — MaxPool2d
// Forward: store argmax flat index for each output position
max_indices[out_flat] = max_idx;  // flat index into input

// Backward: route gradient only to the max position
std::vector<float> grad_input(N * C * H_in * W_in, 0.0f);
for (int i = 0; i < total_out; ++i) {
    grad_input[max_indices[i]] += grad[i];
}
```

This is why max-pooling works well with ReLU: positions that weren't the maximum also weren't the most active — so routing zero gradient to them makes sense.

### Conv2d backward

The backward pass of a convolution is itself a convolution — specifically, the input gradient is computed by convolving the output gradient with the kernel **flipped 180°** (rotating both spatial dimensions). The kernel gradient is computed by convolving the *input* with the output gradient. This elegant symmetry means the same inner-loop logic used in the forward pass can be reused in the backward pass. *(Note: This process corresponds to what is often called a transposed convolution in deep learning literature).*

## Hierarchical features

The power of CNNs comes from stacking layers. Early layers learn low-level features, while later layers combine these into higher-level representations. This hierarchy emerges purely from training — you don't explicitly program it.

**Visualizing the Hierarchy (MNIST):**
1. **Layer 1:** A "Vertical Edge" kernel slides over a raw "7", producing a feature map that highlights the straight vertical stem. A "Horizontal Edge" kernel highlights the top bar. 
2. **Layer 2:** Deeper kernels look at the *output* of Layer 1. They combine the vertical and horizontal maps to detect a "Corner" or a "Loop".
3. **Linear Layer:** Finally, the flattened layer looks at the corners and loops and confidently declares: "That's a 7."

## Flatten

Before a linear classification head, the 3D feature maps must be flattened to a 1D vector. After MaxPool:

$$8 \times 12 \times 12 = 1152 \text{ features per image}$$

The `Flatten` layer reshapes `[batch, 8, 12, 12]` → `[batch, 1152]`.

```cpp
// From nn/Flatten.h
Tensor forward(const Tensor& input) override {
    int batch = input.shape[0];
    int flat  = input.data.size() / batch;
    return Tensor({batch, flat}, input.data);
}
```

Flatten's backward is the reshape in reverse — the gradient arrives as `[batch, 1152]` and passes through unchanged. The data is already contiguous so no copy is needed; the original shape is stored during forward to enable this.
