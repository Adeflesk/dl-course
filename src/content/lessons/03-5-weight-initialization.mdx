## Why Not Initialize to Zero? (Symmetry Breaking)

The most obvious choice is to initialize all weights to `0.0`. But if all weights are identical, every neuron in a layer will compute the exact same output. During backpropagation, they will receive the exact same gradient update. They will stay mathematically "locked" together forever, acting like one single giant neuron. 

We must initialize weights randomly to **break symmetry**, giving each neuron a slightly different starting point so they can learn different features.

## The Problem: Exploding and Vanishing Gradients

Suppose you initialize a 100-layer neural network with random weights $W \sim \mathcal{N}(0, 1)$ (standard normal).

<div class="callout">
**Shallow vs. Deep Networks (The Seabird Era)**

If you trained a network in the early 2000s (like a 1-hidden-layer network for the Seabird project), bad initialization didn't matter nearly as much. The gradient only had to travel backward through two sets of weights. 

But as soon as you move from "Shallow" to "Deep" (dozens or hundreds of layers), the sensitivity to initialization grows exponentially. A "hidden lever" that was ignored 20 years ago is now the difference between a model converging in an hour versus never learning at all.
</div>

During forward pass, each layer computes:
$$z^{(l)} = W^{(l)} \cdot a^{(l-1)} + b^{(l)}$$

If each weight is $\sim \mathcal{N}(0, 1)$ and you have $n$ inputs to a layer, the output variance grows:

$$\text{Var}(z^{(l)}) = n \cdot \text{Var}(W^{(l)}) \cdot \text{Var}(a^{(l-1)}) = n \cdot 1 \cdot \text{Var}(a^{(l-1)})$$

**After 100 layers:** variance explodes! $z$ becomes huge, activations saturate (sigmoid/tanh near 0 or 1), and gradients vanish.

Similarly, during backprop, gradients multiply by weight matrices layer-by-layer. If weights are too small, gradients shrink. If too large, they explode.

## Xavier Initialization

**Xavier (Glorot) initialization** solves this by scaling weights so that **variance is preserved through each layer**.

The idea: Initialize weights $W$ such that variance of the output equals variance of the input, regardless of layer size.

**Theorem:** For a layer with $n_{in}$ inputs and $n_{out}$ outputs, initialize:
$$W \sim \mathcal{U}\left(-\sqrt{\frac{6}{n_{in} + n_{out}}}, \sqrt{\frac{6}{n_{in} + n_{out}}}\right)$$

Or equivalently (with Gaussian):
$$W \sim \mathcal{N}\left(0, \sqrt{\frac{2}{n_{in} + n_{out}}}\right)$$
*(Note: we are using the convention $\mathcal{N}(\mu, \sigma)$ where the second parameter is the standard deviation. Some texts use $\mathcal{N}(\mu, \sigma^2)$, in which case the variance is $\frac{2}{n_{in} + n_{out}}$.)*

**Why this works:**

For a layer: $z = Wx + b$

$$\text{Var}(z) = \text{Var}(W) \cdot \text{Var}(x) \cdot n_{in}$$

If $\text{Var}(x) = \sigma^2$ (from previous layer), we want $\text{Var}(z) = \sigma^2$:

$$\text{Var}(W) \cdot \sigma^2 \cdot n_{in} = \sigma^2$$
$$\text{Var}(W) = \frac{1}{n_{in}}$$

Similarly, for backprop (propagating gradients backward), we derive $\text{Var}(W) = \frac{1}{n_{out}}$.

**Averaging both constraints:**
$$\text{Var}(W) = \frac{1}{\frac{1}{2}(n_{in} + n_{out})} = \frac{2}{n_{in} + n_{out}}$$

This is Xavier initialization!

## He Initialization (The ReLU Factor)

Xavier initialization is perfect for linear layers or symmetric activations (like Sigmoid or Tanh). But as we'll see, modern deep learning relies heavily on **ReLU**. 

ReLU literally "kills" half the input space (any negative number becomes zero). Because half the data is zeroed out, the variance of the output is effectively cut in half! If you use Xavier with ReLU, your variance will slowly shrink layer by layer, leading right back to vanishing gradients.

**He Initialization (Kaiming Init)** fixes this by simply doubling the variance to compensate for the dead half of the data:

$$\text{Var}(W) = \frac{2}{n_{in}}$$

## Implementation in tensorflowccp

```cpp
// In nn/Linear.h
class Linear : public Module {
    Tensor weight;  // [input_size, output_size]
    Tensor bias;

public:
    Linear(int input_size, int output_size) {
        // Xavier initialization
        float limit = std::sqrt(6.0f / (input_size + output_size));
        
        weight = Tensor::uniform(-limit, limit, {input_size, output_size});
        bias = Tensor::zeros({1, output_size});
    }
    
    Tensor forward(const Tensor& x) override {
        return matmul(x, weight) + bias;
    }
};
```

<div class="callout">
**Engineer's Note: C++ Randomness and Hard Boundaries**

In C++, using `std::rand()` is generally poor practice for Machine Learning. Our `Tensor::uniform` function uses high-quality generators like `std::mt19937` (Mersenne Twister) to ensure the randomness is robust enough to effectively break symmetry.

*Senior Dev Tip:* Why use a Uniform distribution instead of a Gaussian here? While both are mathematically valid for Xavier, drawing from a Uniform distribution imposes "hard boundaries." This guarantees that absolutely no outlier weights are generated, preventing any localized exploding gradients right at initialization.
</div>

## Why This Matters

Without proper initialization:
- Early layers don't learn (vanishing gradients)
- Middle layers explode (overflow, NaN)
- Training fails or is extremely slow

With Xavier:
- **All layers learn at similar rates**
- **Stable variance** through forward and backward pass
- **Fast convergence** without tuning learning rates heavily

## Key Takeaways

1. **Initialization is not "set and forget"** — it fundamentally affects trainability
2. **Xavier preserves variance** through forward and backward pass
3. **Deep networks require careful init** — random init fails beyond ~5 layers
4. **Rule of thumb:** $\text{Var}(W) \approx \frac{1}{n_{in}}$ for forward, $\frac{1}{n_{out}}$ for backward, average them
